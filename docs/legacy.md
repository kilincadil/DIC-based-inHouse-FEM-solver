# Legacy mesh generators

The original DIC-to-Abaqus mesh generators, kept in `legacy/` exactly as first
published. They are the starting point the rest of the repository grew out of,
and they are preserved unchanged so earlier results stay reproducible.

Two scales were covered.

## Microscale — `microscale_abaqus_mesh_generator.py`

A regular grid mesh for pixel-level mapping: one CPS4 element per DIC pixel,
each carrying its own Ludwik material derived from the measured maps.

This is the direct ancestor of `abaqus/inp_writer.py`, which supersedes it. The
differences are worth knowing if you compare results generated by the two:

| | `legacy/microscale_...` | `abaqus/inp_writer.py` |
|---|---|---|
| Node/element ordering | C order, `[row, col]` | Fortran order, `[x, y]` |
| Poisson ratio | 0.3 | 0.3 |
| Plastic table | 20 points over `ep` in [0, 0.2] | 50 points over [0, 0.2] |
| Boundary nodes | one `*Nset` per node, referenced by name | node labels referenced directly |
| Edge displacements | interpolated onto `n+1` points | taken directly from the field |
| Dependency | JAX | NumPy only |

The interpolation step is the substantive one: the legacy generator resamples
each edge from `n` measured values onto `n+1` boundary nodes, whereas the newer
writer expects the caller to supply values already on the node grid. Results
from the two are therefore close but not bit-identical along the boundary.

## Mesoscale — `mesoscale_abaqus_mesh_generator.py`

A triangular mesh at grain level, for cases where the microstructure rather than
the pixel grid sets the discretisation. It reads an existing mesh whose element
sets represent grains and twins, scales it onto the region of interest, and
assigns material properties per grain.

This one has **no replacement** — it remains the only grain-scale path in the
repository.

The mesh itself comes from [CRISTALX](https://github.com/CsatiZoltan/CristalX)
(Csáti et al., 2021), and the per-pixel yield and hardening data follow the
method of Hu et al. (2025).

## Supporting modules

- `read_elsets.py` — parses an Abaqus `.inp` for nodes, elements and named
  element sets, including `generate`-style ranges. The element sets are what
  carry the grain and twin identities.
- `load.py` — loads a folder of numerically-named `.npy` files in numeric order,
  e.g. one file per load step.

Both are imported by the mesoscale generator and are kept beside it.
